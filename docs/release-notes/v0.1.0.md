# Astro Canvas v0.1.0

*The first release.* A node-based infinite canvas for astronomical data — and, for the people this
was built for, the rbcodes analysis GUIs rebuilt as headless, composable nodes.

**[Install it](https://lblogan14.github.io/astro-canvas/install/)** ·
[Quick start](https://lblogan14.github.io/astro-canvas/quickstart/) ·
[Coming from rbcodes](https://lblogan14.github.io/astro-canvas/migrating/) ·
[Changelog](https://github.com/lblogan14/astro-canvas/blob/main/CHANGELOG.md)

## What it is

Load a spectrum, an image or an IFU cube. Wire analysis nodes together. Watch results appear on
the nodes as you change a number, because the engine re-runs only what actually depends on what
you changed. Then save the whole thing as a file, turn it into a form a student can use, run it
over four hundred sightlines, or hand somebody a single `.acw` bundle that carries the inputs'
hashes and reproduces your figure.

The science is in installable node packs. The first two rebuild
[rbcodes](https://github.com/rongmon/rbcodes):

| If you use | You get |
|---|---|
| `launch_specgui` | the same six steps as a **Wizard** — load, redshift, transition, continuum, measure, save — with the continuum masks, the velocity range and the line picker as editors, and your batch CSV as an import |
| `rb_zfind` | **all five search methods at once** on the same spectrum, ranked into one candidate table, with the z-accept editor and an accepted redshift that feeds a measurement downstream |
| `rb_multispec` | the stacked viewer with **the same twenty keystrokes**, and the absorber catalogue and identifications saved in the document rather than in a window |
| `rb_ifuview` | the collapses, the aperture drawer, ds9 regions and moment maps, with cubes **memory-mapped** instead of copied |

The numbers are rbcodes' own: every node calls rbcodes where it imports and a vendored copy of the
same kernel where it does not, and the test suite compares the two at `rtol=1e-9`. File formats
round-trip in both directions, so you can start a measurement in one and finish it in the other.

## Getting it

=== "macOS and Linux"

    ```sh
    curl -fsSL https://raw.githubusercontent.com/lblogan14/astro-canvas/main/launcher/install.sh | sh
    ```

=== "Windows"

    ```powershell
    irm https://raw.githubusercontent.com/lblogan14/astro-canvas/main/launcher/install.ps1 | iex
    ```

=== "uv"

    ```sh
    uv tool install 'astro-canvas[rbcodes]'
    astro-canvas open
    ```

=== "A lab server"

    ```sh
    cp deploy/.env.example deploy/.env    # POSTGRES_PASSWORD, CANVAS_DOMAIN, ADMIN_EMAILS
    docker compose -f deploy/compose.yaml up -d --build
    ```

Click-to-run installers (`.exe`, `.dmg`, `.AppImage`) are attached to this release with a
`SHA256SUMS` file. **They are not code-signed**: Windows SmartScreen and macOS Gatekeeper will
warn, and the [install pages](https://lblogan14.github.io/astro-canvas/install/) say exactly which
button to press. A fresh install is 55 packages and about 330 MB.

## Highlights

**Reactive, not batch.** Dirtiness comes from a content hash over a node's type, version,
parameters and its inputs' hashes — not from edit events. Rename a node and nothing re-runs;
change a continuum order and the continuum fit and the equivalent width do. Expensive nodes run in
a worker process and wait for **Run**, and pressing Cancel actually kills them.

**The schema is the contract.** A node is a plain Python function. Its annotations become ports,
its parameters become widgets, and its docstring becomes the help text in the app — there is no
separate UI to write. [Wrap a function as a
node](https://lblogan14.github.io/astro-canvas/packs/tutorial/) builds a complete pack in twenty
minutes.

**One document, four interfaces.** Star a parameter and pin a preview, and the same workflow is a
canvas, a form, a step-by-step wizard, or a dashboard of linked views where a range dragged on a
spectrum highlights the matching rows of a table fed by it. The layout is in the URL, so a link
opens straight into it.

**Reproducible by construction.** A `.acw` bundle carries the document, a dependency lock, the
hash of every input file, the cached results, the figures and a per-node provenance record.
Importing one tells you what is missing instead of guessing.

**It runs without a browser.** `astro-canvas run workflow.json` produces the same outputs on a
cluster node.

## Measured, not asserted

| | |
|---|---|
| 500 nodes, pan and zoom | **56 fps** — 94 % of the display's own ceiling |
| A cheap re-run, debounce excluded | **35 ms** (gate: 300 ms) |
| A million-point spectrum, previewed | **10 ms** |
| A 97 MB IFU cube, white light | **115 ms** at 805 MB/s |
| The same cube, read back from cache | **19 ms**, memory-mapped |
| A 200-row batch | **1.2 s**, and the resident set comes back to where it started |
| axe-core, WCAG 2.1 AA | **zero** serious or critical violations on every audited surface |

All of it is a gate in the test suite rather than a claim; the numbers and how they are taken are
in [performance](https://lblogan14.github.io/astro-canvas/dev/performance/) and
[accessibility](https://lblogan14.github.io/astro-canvas/dev/accessibility/).

## What it does not do yet

- **LLS and Voigt profile fitting** (`IGM.LLSFitter`, `LLSVoigtFitter`), **`rb_align`** and
  **`rb_zgui`** are not ported.
- **Nothing is signed** (see above).
- **A lab server is sized by its concurrent users**: each account's engine lives until the process
  restarts.
- **The code node's sandbox is a denylist**, not a jail. The trust gate is the real protection.
- **English only**, though every string goes through the translation layer.

The full list is in the [changelog](https://github.com/lblogan14/astro-canvas/blob/main/CHANGELOG.md#known-limitations).
